git-grass Developer Documentation

Complete installation, configuration, Git hook behavior, and operational guide for the git-grass developer toolchain.

Prerequisites

  • Node.js: Version 18.0.0 or later (verified on Node 18, 20, 22, and 24).
  • Git: Version 2.20 or later accessible in your system PATH.
  • Operating System: macOS, Linux, or Windows (PowerShell and bash supported).
  • Local Network: Computer and mobile phone connected to the same Wi-Fi network or mobile hotspot for mobile check-in.

Installation

Install the CLI globally from npm registry or clone from source:

bash — npm install 
npm install -g git-grass

Alternatively, clone the repository directly:

bash — source build 
git clone https://github.com/sn3hhaa/git-grass.git
cd git-grass
npm install
npm run build

Repository Initialization

In any Git repository where you want outdoor break enforcement, run:

bash 
git grass init

This command performs three safe setup steps:

  1. Creates the .git-grass/ directory with default repository configuration.
  2. Inspects your existing .git/hooks/pre-commit hook.
  3. Wraps the hook with git-grass delimiters without modifying your linters or tests.

CLI Commands Reference

git grass init

Initializes git-grass in the current repository and installs the pre-commit hook.

git grass status

Displays elapsed focus time since your last break, current break requirements, and active timers.

git grass check

Called automatically during git commit. Evaluates if a break is due. If due, launches the session server with the terminal prompt.

git grass config [key] [value]

Inspects or updates repository-specific configuration values.

bash 
git grass config breakIntervalMinutes 90     # Set break interval to 90 min
git grass config defaultDurationMinutes 20   # Set walk duration to 20 min
git grass config autoPush true               # Auto-push after commit

git grass doctor

Diagnoses environment readiness: Node.js version, Git availability, configuration, and offline fallback catalog.

git grass challenge [--test]

Previews and validates challenge generation for the current repository without triggering a commit.

git grass uninstall [--yes]

Safely removes git-grass pre-commit hooks and deletes .git-grass/, restoring custom hooks.

Staged Index Fingerprinting

When a break is enforced, git-grass immediately executes git write-tree to compute the cryptographic SHA of your current staging index.

When you return from outside and submit your commit from your phone, git-grass re-verifies the index hash before committing. If any staged file was modified or altered while you were outside, the commit halts immediately to prevent committing unexpected changes.

Hosted AI Setup (Render + Backboard)

git-grass connects to a lightweight cloud API deployed on Render's Free tier backed by Backboard. This provides real AI-generated, project-aware challenges with zero local AI installations and ₹0 in additional costs.

Deploying via render.yaml

  1. Fork or connect the repository to Render.
  2. Create a new Web Service using the included render.yaml blueprint.
  3. Set your Backboard API key in the Render environment variables: BACKBOARD_API_KEY=<key>.
  4. Deploy the service on the Free plan.

Emergency Commit Bypass

If you need to ship an urgent hotfix or security patch without taking a break, use Git's standard pre-commit bypass flag:

bash 
git commit --no-verify -m "fix: emergency security patch"

Troubleshooting Guide

Phone cannot connect to session URL?
Ensure both your workstation and phone are on the same local Wi-Fi network or mobile hotspot. If on an enterprise network with client isolation, use your phone's personal hotspot.
Offline or no internet connectivity?
git-grass is offline-first. If no network or hosted backend is configured, it instantly falls back to the bundled catalog of curated outdoor challenges with zero latency.
