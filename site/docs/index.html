git-grass Developer Documentation

Complete installation, configuration, and operational guide for git-grass.

Prerequisites

  • Node.js: Version 18.0.0 or later (verified on Node 18, 20, 22, and 24).
  • Git: Version 2.20 or later accessible in your system PATH.
  • Operating System: macOS, Linux, or Windows (tested on PowerShell and bash).
  • Local Network: Computer and mobile phone connected to the same Wi-Fi network or mobile hotspot for QR code check-in.

Installation

Clone the repository and install dependencies:

bash 
git clone https://github.com/sn3hhaa/git-grass.git
cd git-grass
npm install
npm run build

Optionally link globally so git grass can be run from any repository on your machine:

bash 
npm link

Repository Initialization

In any Git repository where you want outdoor break gating, run:

bash 
git grass init

This command performs three safe setup steps:

  1. Creates the .git-grass/ directory with default configuration.
  2. Inspects your existing .git/hooks/pre-commit hook.
  3. Wraps the hook with git-grass delimiters without overwriting or deleting any of your existing linters or test scripts.

CLI Commands Reference

git grass init

Initializes git-grass in the current Git repository and installs the pre-commit hook.

git grass status

Displays elapsed focus time since your last completed outdoor break, current break requirement status, and active session timers.

git grass check

Called automatically by Git during git commit. Evaluates whether a break is due. If due, exits with code 1 and launches the session server with the terminal QR code.

git grass config [key] [value]

Inspects or updates repository-specific configuration values.

bash 
git grass config breakIntervalMinutes 90     # Set break interval to 90 min
git grass config defaultDurationMinutes 20   # Set walk duration to 20 min
git grass config autoPush true               # Enable auto-push after commit

git grass doctor

Diagnoses environment readiness: Node.js version, Git availability, repository configuration, Render hosted AI connectivity, and bundled fallback datasets.

git grass challenge [--test]

Previews and validates challenge generation for the current repository without triggering a Git commit or starting a break session.

git grass uninstall [--yes]

Safely removes git-grass pre-commit hooks and deletes .git-grass/. Strictly restores your original custom hooks.

Hosted AI Setup (Render + Backboard)

git-grass connects to a lightweight cloud API deployed on Render's Free tier backed by Backboard. This gives you real AI-generated, project-aware challenges with zero local AI installations and ₹0 in additional costs.

Deploying via render.yaml

  1. Fork or connect the repository to Render.
  2. Create a new Web Service using the included render.yaml blueprint.
  3. Set your Backboard API key in the Render environment variables: BACKBOARD_API_KEY=<key>.
  4. Deploy the service on the Free plan.

Once deployed, point your local CLI to your service URL:

bash 
git grass config hostedBackendUrl https://your-service.onrender.com
git grass doctor

Staged Index Fingerprinting

When a break is enforced, git-grass immediately executes git write-tree to compute the cryptographic SHA of your current staging index.

When you return from outside and submit your commit from your phone, git-grass re-verifies the index hash before committing. If any staged file was modified, deleted, or altered while you were outside, the commit halts immediately to prevent committing unexpected changes.

Emergency Commit Bypass

If you need to ship an urgent hotfix or security patch without taking a break, use Git's standard pre-commit bypass flag:

bash 
git commit --no-verify -m "fix: emergency security patch"

Troubleshooting Guide

⚠️
Phone cannot connect to QR URL?
Ensure both your workstation and phone are on the same local Wi-Fi network or mobile hotspot. If on an enterprise network with client isolation, use your phone's personal hotspot.
💡
Render backend timing out?
Render Free Web Services spin down after 15 minutes of inactivity. When woken up, initial start takes ~50 seconds. git-grass has a built-in fast timeout and seamlessly falls back to bundled offline challenges if the service is asleep.
