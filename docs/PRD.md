# Product Requirements Document (PRD) — git-grass

**Product Name:** git-grass  
**Tagline:** Your AI can write the code. It can't touch grass.  
**Repository:** https://github.com/sn3hhaa/git-grass  
**Category:** Developer Tooling / Workflow Automation / Cognitive Wellness  
**Author:** Sneha Tiwari & git-grass Core Team  
**Status:** Approved & Implemented (MVP v0.1.0)  

---

## 1. Executive Summary & Vision

With modern generative AI assistants, IDE copilots, and continuous integration loops, developers spend unprecedented unbroken hours seated in front of digital displays. Existing break reminder notifications are frictionless to dismiss, snooze, or ignore.

**git-grass** shifts the paradigm by integrating physical recovery directly into the developer's source control gate: **Git**. When a configured focus interval expires, the developer's next `git commit` is paused. The CLI generates a QR code opening a mobile web experience tailored with a project-aware outdoor challenge generated by local AI (or curated offline domain fallbacks).

The developer locks their phone, steps outside into the real world for at least 10 minutes, and completes an observational challenge. Upon returning, they submit a reflection and commit message on their phone to release the gate and execute their commit locally.

---

## 2. Problem Statement

1. **Digital Tunnel Vision:** High-velocity coding leads to physical strain, cognitive fatigue, and diminished architectural clarity.
2. **Dismissible Warnings:** Desktop notifications and pop-up banners are routinely ignored within 500 milliseconds.
3. **Screen-Bound Break Apps:** Most wellness apps encourage screen usage (swiping, games, phone feeds) during breaks, defeating ocular and mental recovery.
4. **Heavyweight Infrastructure:** Existing enterprise health tools require accounts, cloud databases, paid subscriptions, or invasive employee monitoring.

---

## 3. Target Users & Personas

- **Autonomous Developers:** Programmers who want disciplined cadence in long coding sessions without external management surveillance.
- **AI-Assisted Engineers:** Developers using LLMs to generate high volumes of code who need deliberate pauses to reflect on system architecture.
- **Open-Source Maintainers:** Engineers juggling reviews and commits who want healthy habits embedded directly into terminal workflows.
- **Students & Hackathon Builders:** Programmers participating in intensive sprints who need enforced rest intervals.

## 4. User Stories

| ID | User Story | Acceptance Criteria |
|---|---|---|
| US-01 | As a developer, I want to initialize git-grass in my repo with one command so that I do not need complex manual setup. | `git grass init` sets up `.git-grass/config.json` and installs pre-commit hook safely. |
| US-02 | As a developer, I want my staged changes strictly preserved when a break is triggered so that my work is never lost. | Staged index is fingerprinted (`git write-tree`) and never modified by the gate. |
| US-03 | As a developer, I want my outdoor challenge to relate to my project domain rather than generic fitness tips. | AI engine extracts project keywords/README and generates contextual observational tasks. |
| US-04 | As a developer, I want to take a break without carrying my laptop or staring at my phone. | Mobile web UI instructs user to lock screen; authoritative timing is kept on server. |
| US-05 | As a developer, I want git-grass to work completely offline with zero API keys or cloud dependencies. | Curated fallback challenge dataset operates without internet or AI servers. |
| US-06 | As a developer, I want to commit my code directly after returning from my walk from my phone. | Mobile check-in submits commit message and triggers local Git execution. |

## 5. Functional Requirements

### 5.1 CLI & Git Integration
- **FR-1.1:** CLI binary named `git-grass`, invokable as `git grass <command>`.
- **FR-1.2:** `git grass init` installs a pre-commit hook into `.git/hooks/pre-commit`.
- **FR-1.3:** Existing hooks must be wrapped and preserved; never blindly overwritten.
- **FR-1.4:** `git grass check` must exit `0` when no break is due, and non-zero when a break is required.
- **FR-1.5:** Internal commit operations must use a bypass token (`GIT_GRASS_BYPASS_TOKEN`) to prevent recursive hook execution.
- **FR-1.6:** `git grass uninstall` must cleanly strip only git-grass hooks and remove `.git-grass/`.

### 5.2 Session Management & Security
- **FR-2.1:** Minimum break duration cannot be configured or executed below 10 minutes.
- **FR-2.2:** Cryptographically random session tokens (48-char hex) must authenticate all mobile requests.
- **FR-2.3:** Session timestamps on the server are authoritative; client clock manipulation is rejected.
- **FR-2.4:** Staged tree SHA is verified before commit execution.

### 5.3 Local Server & Mobile Experience
- **FR-3.1:** Local HTTP server binds to LAN IP on port 4242 (or fallback dynamic port).
- **FR-3.2:** Terminal QR code encodes the session URL with token.
- **FR-3.3:** Mobile interface requires zero app installation (pure HTML5/CSS3/Vanilla JS).
- **FR-3.4:** Mobile UI supports 10 distinct states: loading, setup, challenge, timer, check-in, commit, success, error.

### 5.4 AI & Challenge Engine
- **FR-4.1:** Local AI inference supports Ollama (`gemma:2b`, `gemma2`).
- **FR-4.2:** AI requests are bounded by strict timeouts (6-8 seconds) and failover to bundled library.
- **FR-4.3:** Challenges must be strictly physical and outdoor; zero code testing, zero shell execution.
- **FR-4.4:** Fallback library covers 6 domains: GameDev, Audio/Media, ML/Vision, Web/UI, Systems/DevOps, General.

---

## 6. Non-Functional Requirements

- **Budget:** $0. No paid APIs, cloud services, or hosting accounts.
- **Zero Shell Injection:** Child processes must be executed with argument arrays (`execFile`/`spawn`).
- **Performance:** `git grass check` when not due must execute in < 80ms.
- **Portability:** Cross-platform support for Windows, macOS, and Linux.
- **Accessibility:** High-contrast mobile typography legible outdoors in direct sunlight; reduced-motion CSS support.

---

## 7. Out-of-Scope (Non-Goals for MVP)

- GPS surveillance or satellite tracking of physical movement.
- Wearable fitness tracker integration (Apple Health, Garmin, Fitbit).
- Public cloud synchronization or team leaderboards.
- Facial recognition or webcam presence verification.
- Mandatory social sharing.

---

## 8. Success Metrics

1. **Commit Integrity:** 100% preservation of staged Git state across all sessions.
2. **Zero Inadvertent Bypass:** Hooks reliably prevent commits until verified.
3. **Zero Cost & Zero Keys:** 100% operational out of the box with zero external configuration.
4. **Developer Restoration:** 10+ minutes of screen-free outdoor activity achieved per completed session.
